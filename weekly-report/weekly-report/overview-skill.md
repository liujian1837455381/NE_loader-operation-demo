# 装载机运营周报·全站总览分析 Skill

## 1. 适用范围

本 Skill 用于一次性生成运营周报第一部分「汇总运营指标分析」（10 条结构）。

输入为一张「各站点运营情况」周报总表的 **TSV 文本**（非截图），结构特征：
- 标题形如 `X.X~X.X各站点运营情况`；
- 横向为多个站点列（演示站A、演示站B、演示站I、演示站F、演示站H、演示站E…），每站含「上周目标 / 上周完成 / 本周目标」三列；
- 右侧为「本周合计（上周目标/上周完成/本周目标）」「前一周期」「同比前一周变化」；
- 纵向指标分「效果、时长、上料数」三组。

输出目标：根据 TSV 数据，稳定生成风格一致、字数相近、不过度发挥的 10 条汇总分析。

---

## 2. 输出风格总原则

1. 中文商务周报口吻，句式简洁、客观。
2. 只写表格能支撑的信息。本表不含故障/接管原因文本，**不得编造原因**；原因类描述一律写「具体原因待补充」或省略，绝不使用未在表中出现的原因。
3. 不要写成咨询报告，不主动给优化建议。
4. 汇总分析以「整体指标表现 + 达标/未达标 + 同比变化」为主，不要逐站点重复罗列。
5. 不使用 Markdown 加粗符号 `**`/`*`；数字写成纯文本，如 `139h`、`82.01%`、`1,336次`。
6. 一次性输出完整 10 条，不要等待后续交互，不要输出单站点明细。
7. 各条之间直接换行，**不要留空行**（第1条末尾换行接第2条，中间无空行）。

---

## 3. TSV 读取方法

### 3.1 识别周期和站点

- 周期：从标题或表头读 `开始日期~结束日期`。
- 站点：表头中每个占 3 列（上周目标/上周完成/本周目标）的列名即站点。
- 站点名沿用 TSV 原文写法（如 `演示站A`、`演示站B`、`演示站F`、`演示站H`、`演示站I`、`演示站E`）。

### 3.2 读取本周合计

优先取右侧「本周合计」的「上周完成」列作为本周全站实际完成值。各组指标：

- 效果：AI时长接管率、生产任务接管率、任务成功率、异常任务远程恢复率、生产时长覆盖率、自动化生产方量覆盖率、人效比、故障频次（次/h）、一级故障占比
- 时长：运营天数、总运营时长（h）
- 上料数：自动上料总数、测试上料数、自动生产上料数、手动上料数、总生产方量、人工接管生产方量、自动化生产方量

### 3.3 判断达标/未达标

对比「本周合计」的「上周完成」与「本周目标」：
- 完成值 ≥ 目标值：达标。
- 完成值 < 目标值：未达标。
- 故障频次越低越好，不按常规比率判断。
- 目标为 `/`、空白时，不做达标判定，只列完成值。

### 3.4 读取同比变化

从右侧「同比前一周变化」列读取：
- 正值且指标越高越好 →「同比提升 X% / 增加 Xh / 增加 X次」。
- 负值 →「同比下降 X% / 减少 Xh / 减少 X次」。
- 故障频次当前值低于前一周期 →「同比改善 X次/h」；高于 →「同比增加 X次/h」。

---

## 4. 输出结构（固定 10 条）

### 1.运营概况

总览站点数量、整体亮点、主要问题。简略，只挑 2~3 个对整体影响最大的站点或指标，不堆砌所有异常。

模板：
`1.运营概况：本周共运营X个站点，分别为A、B、C。本周总运营时长较前一周期增加/减少，XX指标整体达标/有所提升；但XX、XX指标未达标。主要问题集中在A站XX指标偏低、B站XX指标未达标。（原因待补充）`

### 2.总运营时间

取「本周合计-总运营时长（h）」与同比。

模板：
`2.总运营时间：Xh，同比增加/减少Yh，主要受本周运营天数/站点数变化影响；（具体原因待补充）；`

### 3.总上料数

统一口径：`累计X次 = 自动化Y次 + 手动上料Z次`；`自动化Y次`对应「自动上料总数」，含「自动生产上料数A」和「测试上料数B」；`手动上料Z次`对应「手动上料数」。自动化异常任务不计入累计。

模板：
`3.总上料数：累计X次（自动化Y次，含自动生产A次、测试B次；另外手动上料Z次），自动化上料同比增加/下降X次，自动生产上料同比增加/下降X次，手动上料同比增加/减少X次，整体自动化作业占比提升/下降；`

### 4.总AI时长接管率

不逐站罗列，只讲整体达标与否和同比，必要时点名最关键站点（仅数据层面，不编原因）。

模板：
`4.总AI时长接管率：X%，同比提升/下降Y%。整体达到/未达到目标（Z%），本周AI接管表现整体较好/偏弱；（具体原因待补充）；`

### 5.总生产任务接管率

模板：
`5.总生产任务接管率：X%，同比提升/下降Y%。整体达到/未达到目标（Z%），主要受自动化生产任务占比影响；（具体原因待补充）；`

### 6.总任务成功率

模板：
`6.总任务成功率：X%，同比提升/下降Y%。整体达到/未达到目标（Z%），本周任务执行稳定性较前一周期改善/下降；若下降，主要受A站成功率偏低拉低整体；（具体原因待补充）；`

### 7.总异常任务远程恢复率

异常数量少时说明比例易波动。

模板：
`7.总异常任务远程恢复率：X%，同比提升/下降Y%。整体达到/未达到目标（Z%），主要受部分站点异常数量较少、个别异常未能远程恢复影响；（具体原因待补充）；`

### 8.总生产时长覆盖率

模板：
`8.总生产时长覆盖率：X%，同比提升/下降Y%，整体达到目标（Z%）。各生产站点整体覆盖情况较好；（具体原因待补充）；`

### 9.自动化生产方量覆盖率

模板：
`9.自动化生产方量覆盖率：X%，同比提升/下降Y%，整体达到/未达到目标（Z%）。本周自动化生产方量为A方，同比增加/减少B方；（具体原因待补充）；`

### 10.故障及分布

按故障频次和一级故障占比写。

模板：
`10.故障及分布：故障频次X次/h，同比改善/增加Y次/h，故障频次较前一周期下降/上升。一级故障占比为A%；（故障明细与分布待补充）。`

---

## 5. 异常解释原则

1. 同一问题影响多个指标时，只在最合适的位置提一次（本表无原因文本时，相关位置统一写「原因待补充」）。
2. 汇总指标不逐站点罗列百分比；点名只挑对整体影响最大的 1~2 个站点，且只陈述其数据表现（达标/未达标、偏低/偏高），不编原因。
3. 达标但同比下降 → 写「整体达到目标，但较前一周期有所下降」。

---

## 6. 数据一致性检查（输出前自检）

1. 站点数量和名称与 TSV 表头一致。
2. 总运营时间取「本周合计-总运营时长」。
3. 总上料数 = 自动化 + 手动。
4. 自动化上料、自动生产、测试、手动上料对应正确行。
5. 同比变化正负方向正确。
6. 达标/未达标按目标判断；目标为 `/` 时只列完成值。
7. 不出现编造的原因。
8. 不重复解释同一原因。
9. 不误用「环比」或「同比上一年」，统一用「同比前一周变化」。

---

## 7. 禁止事项

1. 不编造任何未在 TSV 中出现的原因、故障、建议。
2. 不逐站点机械罗列百分比（除非该站点是对整体影响最大的关键站点）。
3. 不使用 `**`、`*` 等 Markdown 加粗符号或隐藏格式字符。
4. 不把自动化异常任务计入累计上料数。
5. 不把目标为 `/` 的指标写成达标或未达标。
6. 不输出单站点明细或等待后续交互——一次性输出完整 10 条。
